# Development

How to run kino.wtf locally. For how the system fits together, see [ARCHITECTURE.md](ARCHITECTURE.md).

## Prerequisites

- Node.js 22.13+
- Yarn 1.x
- A Supabase project, for anything that touches games or accounts (see [SUPABASE.md](SUPABASE.md))
- Python 3.12, only for the game data pipeline (see [get_games/README.md](../get_games/README.md))

## Quick start

```sh
yarn install
cp .env.example .env   # then set VITE_SUPABASE_URL and VITE_SUPABASE_KEY
yarn dev
```

Open the local URL that `yarn dev` prints.

## Scripts

| Command                             | What it does                                                   |
| ----------------------------------- | -------------------------------------------------------------- |
| `yarn dev`                          | Development server                                             |
| `yarn build`                        | Production build with prerendering, then `tsc --noEmit`        |
| `yarn start`                        | Serve the built output from `.output/server/index.mjs`         |
| `yarn preview`                      | Preview the production build                                   |
| `yarn lint`                         | ESLint                                                         |
| `yarn test` / `yarn test:watch`     | Vitest, including the SQL migration tests in `supabase/tests/` |
| `yarn format` / `yarn format:check` | Prettier                                                       |
| `yarn db:migration:new -- <name>`   | Create a timestamped migration in `supabase/migrations/`       |

Before opening a pull request, run `yarn format:check && yarn lint && yarn test && yarn build`. CI runs the same checks.

## Environment

| Variable                 | Required | Purpose                                                                      |
| ------------------------ | -------- | ---------------------------------------------------------------------------- |
| `VITE_SUPABASE_URL`      | Yes      | Supabase project URL                                                         |
| `VITE_SUPABASE_KEY`      | Yes      | Supabase anon (public) key                                                   |
| `VITE_AUTH_REDIRECT_URL` | No       | Canonical base URL for auth redirects, e.g. `https://kino.wtf` in production |

The pipeline in `get_games/` uses its own variables (`TMDB_API_TOKEN`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`). Never put the service-role key in a `VITE_` variable: those are bundled into the client.

## Development modes

- **Frontend only.** Without a `.env` (or with the placeholder values), the app shell, home page, and static pages run, auth and sync are disabled, and game routes show "no games available" because the catalog lives in Supabase. Good for UI and layout work.
- **Supabase-enabled.** With a configured project and migrations applied, everything works: games, auth, sync, history, and leaderboards. Setup is in [SUPABASE.md](SUPABASE.md).
- **Game data.** Generating and appending games uses the Python tooling in `get_games/`. See [get_games/README.md](../get_games/README.md).

## TanStack Start notes

- Vite runs the TanStack Start plugin (`vite.config.ts`) in SPA mode with prerender crawling; prerendered pages are generated during `yarn build`.
- `vercel.json` rewrites unmatched requests to `/_shell.html` so client-side routing works in production.
- `index.html` is intentionally minimal; document head metadata lives in `src/routes/__root.tsx`.
- The route tree in `src/routeTree.gen.ts` is regenerated by the dev server and build.

## Tips

**Next-game boundary in development.** On a game page in a development build, run:

```js
window.__simulateNextBoundary();
```

This writes a fresh local draft for the next index and dispatches a `storage` event, so you can check how the page reacts to a new game without waiting for a release. It only changes local state; which games are released is decided in Supabase.

**Releasing a game against a dev database.** Releases normally come from pg_cron. To release immediately in a development project, run `select * from public.release_next_games();` in the SQL editor (it still releases at most one game per mode per period).

## Troubleshooting

- **Route changes don't show up:** restart the dev server so the route tree regenerates.
- **Theme changes don't persist:** clear the theme keys in localStorage and reload.
- **Game routes say no games are available:** check the Supabase variables, that migrations are applied, and that `game_releases` has rows (`select game_mode, max(game_index) from game_releases group by 1`).
- **Dataset generation fails:** check that `TMDB_API_TOKEN` is set and valid.
